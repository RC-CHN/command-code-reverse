核对日期：2026-09-22。目标场景为 k8s 中长期运行的代理实例，同一设备切换多个上游账号。

## CLI 证据

- 3637–3690：遥测 session 由进程启动生成，格式为 `sess_` 加 16 个无连字符的 UUID 十六进制字符。
- 34611–34630：请求配置的日期来自 `new Date().toISOString()`，使用 UTC；不是设备时区的本地日期。
- 44800–44930：设备字段包括平台、架构、系统版本、CPU/核心数、内存、容器标记和时区；内存四舍五入为 GiB。
  指纹上报受 telemetry 开关约束，进程内首次尝试后不自动重试。
- 112701–112772：CLI 启动初始化遥测，发送 `cli_session_exists`；版本取 CLI 包版本；
  `mode` 为有 TTY 时的 `interactive` 或无 TTY 时的 `non-interactive`。

## 代理的生命周期模型

长期代理不会一比一对应单个 CLI 进程，以下是明确的模拟策略，不是已确认的上游强制要求。

| 维度 | 行为 |
|---|---|
| 设备 | 同一实例所有 key 共用一个完整设备档案；seed 相同则跨节点、跨进程一致 |
| 激活 | 仅实际发送的 chat/Jev 请求收到上游 2xx 后激活对应 key |
| 不激活 | 池中闲置账号、被拒绝或未发送的请求、模型目录、余额、readiness、遥测自身 |
| 活动期 | 在途响应一直活跃；EOF、读错误或 Close 后计入最后活动时间 |
| 空闲期 | `FINGERPRINT_SESSION_IDLE_SECONDS`，默认 1800 秒，按 seed/key 固定偏移 ±20% |
| 过期 | 只改变本地会话判断，不发心搏、不探测账号；下次实际推理才建立新遥测会话 |
| 版本变化 | 下次实际推理建立新遥测会话；事件及请求头固定使用激活它的推理版本 |
| 对话 | conversation root 派生的 session/thread/project 身份不随遥测过期重置；原有跨账号规则保留 |
| 日期 | 保留 CLI 的 UTC 日期，避免与源码相反地改成设备本地日期 |
| 并发 | 同账号同活动期去重；多个不同对话可并行，长流不会被空闲期限提前过期 |
| 故障 | 遥测失败不阻塞推理、不影响任一熔断器；同一活动会话不重试 |
| 资源限制 | 2 个后台 worker、64 项队列、4096 项账号 hash 表；容量不足只跳过遥测 |
| 队列延迟 | 发送前检查是否仍为当前活动会话，过期或被替换的任务丢弃 |

多副本不引入共享数据库：同 seed 表示同一设备的多个 CLI 进程，各副本只管理自己真正使用的账号。
这不会保证所有流量不可识别；协议必需的共同字段保持原样，客户端一致性不能证明风控效果。

## 完整 seed 档案

`profile.go` 中的 v1 规则固定 CPU/架构组合、vCPU 与内存配比，并派生系统版本、时区、容器标记、
MAC 数量和身份哈希。生成只依赖 seed，不读硬件、不看环境变量、不读写状态文件。
未设置 seed 时才读取实际硬件，缺失项用启动时随机种子补齐，随后固定，并兼容状态文件重放。

旧实现只有身份哈希依赖 seed，硬件统一为 `Virtual CPU / 4 核 / 16 GiB / 3 MAC`，
其余部分依赖当前宿主机；因此 v0.2.0 首次升级可能改变原来的 thumbmark。
新规则以完整序列化结果的固定 SHA-256 测试向量锁定，禁止悄悄改动已有 v1 设备。
